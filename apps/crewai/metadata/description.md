# CrewAI Studio (+ Qdrant & Redis)

**What it is:** A Streamlit UI for building and running CrewAI agents, bundled with **Qdrant** (vector DB) and **Redis** (cache/queues) so RAG + fast state work out of the box.

---

## Highlights
- **One-click setup**: CrewAI Studio + Qdrant + Redis on a private network.
- **Persistence**: App data, Qdrant storage, and Redis AOF are volume-mounted.
- **Health-gated startup**: Studio waits until Qdrant/Redis are healthy.
- **Internal by default**: Only Studio is exposed; Qdrant/Redis stay internal.

> Architectures: current image targets `amd64`.

---

## How to use

### 1) Pick your LLM backend
In the install form you can set:
- `OPENAI_BASE_URL` (e.g. `http://192.168.1.12:8080/v1` for LocalAI)  
- `OPENAI_API_KEY` (or a dummy key for OpenAI-compatible local backends)  
- Optional: `OLLAMA_BASE_URL`, `ANTHROPIC_API_KEY`, `GROQ_API_KEY`, `LMSTUDIO_BASE_URL`

### 2) Vector DB & Cache
These are prewired into the Studio container via env vars:

- **Qdrant**
  - `QDRANT_URL= http://qdrant:6333`
  - `QDRANT_GRPC_URL= http://qdrant:6334`
  - `QDRANT_COLLECTION` (default: `crewai`)
  - `QDRANT_API_KEY` (optional; enables auth on bundled Qdrant)

- **Redis**
  - `REDIS_HOST= redis`
  - `REDIS_PORT= 6379`
  - `REDIS_PASSWORD` (optional; autogenerated if blank)
  - `REDIS_URL= redis://:<password>@redis:6379/0` (set automatically)

Use these directly in your CrewAI tools, memory stores, or custom code.

## Data & Persistence

| Component       | Host path                             | Container path       |
|----------------|----------------------------------------|----------------------|
| Studio data    | `${APP_DATA_DIR}/data`                 | `/data`              |
| Qdrant storage | `${APP_DATA_DIR}/qdrant/storage`       | `/qdrant/storage`    |
| Redis AOF      | `${APP_DATA_DIR}/redis`                | `/data`              |

---

## Security & Exposure
- Qdrant and Redis are **not** exposed publicly; they’re reachable only as `qdrant:6333/6334` and `redis:6379` on the app’s internal network.
- To protect Qdrant, you can set `QDRANT_API_KEY` (auth enforced internally). If you later choose to expose Qdrant, add an auth middleware/proxy at the network edge.

---

## Troubleshooting
- If Studio can’t see Qdrant/Redis, verify they show **healthy** in the Runtipi UI.
- If Qdrant auth is enabled (`QDRANT_API_KEY` set), client code must include the key.
- Redis password is optional; when omitted, the instance runs without auth (internal network only).
